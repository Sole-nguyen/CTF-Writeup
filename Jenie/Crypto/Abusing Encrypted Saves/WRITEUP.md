## Challenge Description

A simple game: rock–paper–scissors. And yet a very complex goal: achieve 100 consecutive victories! Will you be able to rise to the challenge?

The game's source code is provided. Only one dependency is required: `pip install cryptography`.

**Connection:** `netcat crypto.jeanne-hack-ctf.org 5000`

## Initial Analysis

Upon examining the provided source code (`server.py`), we discover a Rock-Paper-Scissors game with the following features:

1. Play games against the server (which uses `random.SystemRandom()` for cryptographically secure randomness)
2. View statistics (wins, losses, draws, total games, winrate)
3. **Save progress** - encrypts your stats and provides a base64-encoded save
4. **Load progress** - decrypts and restores your stats from a save
5. Show flag - requires **100 wins** with **100% winrate** (100 total games, 0 losses, 0 draws)

### The Encryption Scheme

Looking at the initialization and save/load functions:


**Key observations:**
- Uses **AES-CTR mode** for encryption
- The key and nonce are randomly generated per session
- Stats are formatted as JSON with 3-digit zero-padded values
- Both plaintext and ciphertext are accessible to us

## The Vulnerability: AES-CTR Bit-Flipping Attack

### Understanding CTR Mode

AES-CTR (Counter Mode) is a **stream cipher** that works as follows:

```
Ciphertext = Plaintext ⊕ Keystream
```

Where the keystream is generated by encrypting sequential counter values with the AES key.

### The Attack

The critical vulnerability is that CTR mode is **malleable**. If we know:
- The original plaintext
- The ciphertext

We can calculate:
```
Keystream = Ciphertext ⊕ Plaintext
```

Then create a modified ciphertext for any target plaintext:
```
Modified_Ciphertext = Target_Plaintext ⊕ Keystream
                    = Target_Plaintext ⊕ Ciphertext ⊕ Plaintext
                    = Ciphertext ⊕ (Plaintext ⊕ Target_Plaintext)
```

This is called a **bit-flipping attack** because we're flipping specific bits in the ciphertext to change the plaintext without knowing the encryption key!

### Why This Works Here

1. When we **save progress**, the server sends us:
   - The plaintext stats: `{"wins": "001", "losses": "000", ...}`
   - The encrypted save (base64-encoded ciphertext)

2. We can XOR them to get the keystream

3. We modify the ciphertext to decrypt to our desired stats:
   - `"wins": "100"`
   - `"total_games": "100"`
   - `"losses": "000"`
   - `"draws": "000"`
   - `"winrate": "100.0"`

4. When we **load progress**, the server decrypts our modified save and updates our stats to 100 wins!

## Solution Strategy

### Step 1: Play at least one game
We need to generate initial stats. Ideally, we want to **win** the first game because:
- Winning gives us: `{"wins": "001", ..., "winrate": "100.0"}` (90 bytes)
- Losing gives us: `{"wins": "000", ..., "winrate": "0.0"}` (88 bytes)

The target state has the same 90-byte length as the winning state, making the bit-flipping easier.

### Step 2: Save progress
Capture both the plaintext stats and the encrypted save.

### Step 3: Perform bit-flipping attack
Calculate the XOR difference between original and target plaintext, then apply it to the ciphertext.

### Step 4: Load the modified save
The server decrypts our modified ciphertext and restores our stats to 100 wins!

### Step 5: Claim the flag
Request the flag with our perfect 100% winrate.

```python
#!/usr/bin/env python3

import socket
import base64
import json

def xor_bytes(b1, b2):
    """XOR two byte strings"""
    return bytes(a ^ b for a, b in zip(b1, b2))

def recv_until(sock, marker):
    """Receive until a marker is found"""
    data = b''
    while marker not in data:
        chunk = sock.recv(1)
        if not chunk:
            break
        data += chunk
    return data.decode()

def exploit():
    # Connect to server
    host = "crypto.jeanne-hack-ctf.org"
    port = 5000
    
    print(f"[*] Connecting to {host}:{port}...")
    s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    s.connect((host, port))
    
    # Receive banner
    banner = recv_until(s, b"> ")
    print(banner)
    
    # Step 1: Play games until we get a win
    print("\n[*] Playing games to generate initial save with a win...")
    
    for game_num in range(1, 4):  # Play up to 3 games
        print(f"\n[Game {game_num}]")
        s.send(b"1\n")

        choice = ((game_num - 1) % 3) + 1
        s.send(f"{choice}\n".encode())

        result = recv_until(s, b"> ")
        print(result.split('\n')[0])
        
        if "You win" in result:
            print("[*] Got a win! Moving to save...")
            break
    
    # Step 2: Save progress
    print("\n[*] Saving progress...")
    s.send(b"3\n")
    
    # Receive save data
    save_data = recv_until(s, b"> ")
    
    # Extract the actual stats and encrypted save
    lines = save_data.split('\n')
    actual_stats_line = [l for l in lines if 'Your actual stats:' in l][0]
    encrypted_save_line = [l for l in lines if 'Your save :' in l][0]
    
    actual_stats_json = actual_stats_line.split('Your actual stats: ')[1].strip()
    encrypted_save_b64 = encrypted_save_line.split('Your save : ')[1].strip()
    
    print(f"\n[*] Original stats: {actual_stats_json}")
    
    # Step 3: Perform bit-flipping attack
    print("\n[*] Performing bit-flipping attack on AES-CTR...")
    
    # The original plaintext we know
    original_plaintext = actual_stats_json.encode()
    original_data = json.loads(actual_stats_json)
    
    print(f"[*] Starting from: wins={original_data['wins']}, "
          f"total={original_data['total_games']}, "
          f"winrate={original_data['winrate']}")
    
    # The target plaintext - must be same length!
    target_stats = {}
    for key in original_data.keys():
        if key == "wins":
            target_stats[key] = "100"
        elif key == "losses":
            target_stats[key] = "000"
        elif key == "draws":
            target_stats[key] = "000"
        elif key == "total_games":
            target_stats[key] = "100"
        elif key == "winrate":
            target_stats[key] = "100.0"
    
    target_plaintext = json.dumps(target_stats).encode()
    
    print(f"[*] Target stats: {target_plaintext.decode()}")
    print(f"[*] Lengths: Original={len(original_plaintext)}, "
          f"Target={len(target_plaintext)}")
    
    # Ensure same length
    if len(original_plaintext) != len(target_plaintext):
        print("[!] Length mismatch - padding target...")
        if len(target_plaintext) < len(original_plaintext):
            target_plaintext = target_plaintext + b' ' * (len(original_plaintext) - len(target_plaintext))
        else:
            print("[!] Target too long - using compact JSON...")
            target_stats_compact = {"wins":"100","losses":"000","draws":"000",

    modified_ciphertext = xor_bytes(encrypted_save, xor_mask)
    
    # Encode back to base64
    modified_save_b64 = base64.b64encode(modified_ciphertext).decode()

        for prefix in ["JDHACK{", "JDH{"]:
            if prefix in flag_response:
                flag_start = flag_response.find(prefix)
                flag_end = flag_response.find("}", flag_start) + 1
                flag = flag_response[flag_start:flag_end]
                print(f"\n\n========== FLAG FOUND ==========")
                print(f"{flag}")
                print(f"================================")
                break
    
    # Close connection
    s.send(b"6\n")
    s.close()
    
    print("\n[*] Done!")

    exploit()
```

## Key Takeaways

### Vulnerabilities
1. **AES-CTR mode without authentication** - CTR mode provides confidentiality but not integrity
2. **Malleable encryption** - Attackers can modify ciphertexts to change the underlying plaintext in predictable ways
3. **Exposing plaintext alongside ciphertext** - Giving both values makes bit-flipping trivial

### Mitigation
To fix this vulnerability, the server should:

1. **Use authenticated encryption** (e.g., AES-GCM, ChaCha20-Poly1305)
   - Provides both confidentiality and integrity
   - Detects any tampering with the ciphertext

2. **Never expose plaintext with ciphertext**
   - Don't send `"Your actual stats: {...}"` before the encrypted save

3. **Use HMAC or digital signatures**
   - Sign the encrypted save to detect modifications
   - Example: `HMAC-SHA256(encrypted_save, secret_key)`

4. **Consider server-side state**
   - Store progress on the server instead of trusting client-provided saves
   - Use session tokens to identify players

### Real-World Impact
This vulnerability class has appeared in:
- Game save files (achievement/progress manipulation)
- Cookie tampering attacks
- JWT token manipulation (when not properly signed)
- Protocol vulnerabilities (WEP, TLS < 1.1 with CBC mode)

Always use **authenticated encryption** when integrity matters!
