# UMASS RE Challenges - Writeup

## Batcave Bitflips

**Overview:** The binary stores `LICENSE_KEY`, an `EXPECTED` hash, a `FLAG` buffer, and an `SBOX` in `.data`. The hash routine expands a 32-byte key into 64 bytes, then repeats `substitute -> mix -> rotate` for `0xBEEEEE + 1` rounds, and folds to 32 bytes.

**Bugs (matches the hints):**
1. **Rotation bug:** `rotate()` uses `shr 6`, but the intended left-rotate-by-3 is `((b << 3) | (b >> 5))`.
2. **SBOX bug:** `SBOX` is not a permutation (duplicate `0x43`, missing `0x44`). The bad duplicate is at index `24`; patch it to `0x44`.
3. **Decrypt bug:** `decrypt_flag` uses **OR** instead of **XOR** with the hashed key.

**Exploit path:**
1. Extract the embedded key: `!_batman-robin-alfred_((67||67))`.
2. Fix the rotate/SBOX bugs so the hash equals `EXPECTED`.
3. XOR the encrypted `FLAG` bytes with `EXPECTED` to recover the flag.

**Flag:** `UMASS{__p4tche5_0n_p4tche$__#}`

## Lego Clicker

**Overview:** The APK delegates session checks to native methods in `liblegocore.so`. There are **fake flags** (e.g., via `FCA`), and the real flag comes from the native `syncBrickCache` implementation.

**Key findings:**
1. `JNI_OnLoad` registers native methods for `SessionValidator`:
   - `validateBrickToken`
   - `refreshTileMap`
   - `syncBrickCache`
2. `FCA` produces a **decoy flag** (`BHREV{...}`), not the real one.
3. `syncBrickCache` builds a 0x29-byte flag via three byte tables and a small chain of XOR/rotate/add/sub transforms.
4. An anti-debug check reads `/proc/self/status` (`TracerPid:`), but its output does not affect the final string (the runtime seed reduces to zero).

**Exploit path:**
1. Emulate the native `syncBrickCache` generator with the extracted tables.
2. Decode the generated bytes as ASCII.

**Flag:** `UMASS{br1ck_by_br1ck_y0u_r3ach3d_th3_t0p}`
